# WorldForge 威胁模型

> 状态：Approved  
> 适用：V1.0桌面单用户、本地优先架构  
> 更新日期：2026-07-30

## 1. 保护资产

- 未发布作品正文、建议稿和历史版本。
- 人物、世界观、时间线、伏笔、设定更新建议证据和研究资料。
- 项目数据库、备份与导出文件。
- API凭据及其密文。
- 作者手动锁定内容。
- 项目路径与本地附件。
- AI请求中的上下文、Prompt与模型响应。
- GenerationRun、Prompt版本和约束来源审计链。
- 搜索、替换、词典、索引和写作辅助的界面状态完整性。

## 2. 信任边界

```text
用户
  ↓
Renderer（不可信输入与展示层）
  ↓ 白名单Preload
Electron Main / Core Service（受信任执行层）
  ↓
SQLite / 项目文件 / safeStorage保护的凭据文件
  ↓ 用户主动配置
外部API或本地模型服务（外部信任域）
```

Renderer展示的数据和所有用户输入均需验证。Provider服务无论在本机、局域网还是外部，都不视为权威数据源，也不能被假定会返回合法、有限或及时结束的响应。

## 3. 主要威胁与缓解

| ID | 威胁 | 影响 | 缓解 |
|---|---|---|---|
| TM-001 | Renderer获得Node或文件能力 | 任意读取本机文件 | 关闭Node集成、启用隔离与sandbox、最小Preload |
| TM-002 | 任意IPC通道或输入未校验 | 越权调用Core能力 | 具名白名单、strict Zod校验、协议版本和命令注册表 |
| TM-003 | 路径穿越或符号链接越界 | 读取或覆盖项目外文件 | Core规范化路径、真实路径检查、允许根目录校验 |
| TM-004 | 跨项目ID混用 | 作品数据串读串写 | 项目作用域、实体归属、章节归属和Repository强制校验 |
| TM-005 | AI直接覆盖当前稿 | 作者正文丢失 | 建议稿隔离、明确接受、保存序号、内容Hash和锁定保护 |
| TM-006 | 旧建议稿覆盖新编辑 | 静默回退作者修改 | 基线保存序号、预期Hash、冲突集 |
| TM-007 | 锁定块被批量操作修改 | 关键文本破坏 | Tiptap事务过滤、Core统一LockGuard、整批Patch回滚 |
| TM-008 | DOCX解包异常内容 | 资源耗尽或越界写入 | 限制大小、数量、压缩比、深度和路径；忽略嵌入对象与外部资源 |
| TM-009 | 凭据写入数据库、Renderer、日志或错误 | 密钥泄露 | safeStorage安全后端、受限密文文件、credentialRef、日志脱敏、错误白名单 |
| TM-010 | safeStorage不可用或使用不安全后端 | 凭据以弱保护形式落盘 | `isEncryptionAvailable`检查；`basic_text`等后端直接阻断 |
| TM-011 | 外部模型端点记录内容 | 作品泄露到第三方 | 明确端点类型、用户主动配置、本机直连、发送类别提示 |
| TM-012 | 危险Provider URL或重定向 | SSRF、本地资源探测、数据外送 | 协议白名单、端点分类、危险地址阻断、跨主机重定向拒绝 |
| TM-013 | 数据库损坏或断电 | 丢稿 | WAL、单写队列、事务、完整性检查和三轨备份 |
| TM-014 | 恢复覆盖原项目 | 二次数据损失 | 默认恢复到新目录，验证后注册为新项目 |
| TM-015 | 日志或诊断包包含正文、Prompt或响应 | 隐私泄露 | 默认只记ID、耗时、计数和Hash；导出前白名单与用户确认 |
| TM-016 | 远程页面在应用内加载 | 页面利用桌面权限 | 禁止导航、新窗口和远程内容；外链交系统浏览器 |
| TM-017 | 恶意导出路径 | 覆盖关键文件 | 系统选择器、目标确认、临时文件和原子重命名 |
| TM-018 | 情节骨架被当作正文建议稿采用 | 结构化规划污染当前稿 | 判别式建议稿合同、Core类型守卫、采用/Version/定稿拒绝 |
| TM-019 | 未完成建议稿被误作完整稿 | 截断正文被整稿采用或定稿 | 完整度硬字段、整稿采用/定稿拒绝、显式补全流程 |
| TM-020 | AI状态提取直接写权威状态 | 人物状态和弧光被未经确认推进 | 只允许pending设定更新建议，作者裁决后单事务更新 |
| TM-021 | pending建议进入约束或校验 | 未确认建议冒充事实 | 权威查询过滤、状态类型校验、只读已确认状态 |
| TM-022 | 取消后迟到delta污染界面 | 已取消内容串入新任务或章节 | 任务代次、Abort、迟到事件消费、Renderer交付阻断 |
| TM-023 | GenerationRun与结果引用断裂 | 审计失真、孤立建议稿或提案 | Run与结果原子收口、外键/完整性检查、重启权威查询 |
| TM-024 | 继续写作状态保存正文 | 应用级偏好泄露作品内容 | 只保存项目、章节、光标、滚动和最小视图状态 |
| TM-025 | 写作统计混入AI、导入或恢复 | 误导作者产出和节奏判断 | mutationOrigin或WritingSession，非人工来源全部排除 |
| TM-026 | Provider返回超大或无界响应 | 内存、字符串缓冲或事件循环资源耗尽 | 16 MiB总响应上限、1 MiB单SSE事件上限、流式累计、超限取消Reader |
| TM-027 | 不同界面异步能力共享请求代次 | 词典操作使搜索或替换失效并永久等待 | 搜索、替换、词典和索引使用独立请求通道与独立等待状态 |
| TM-028 | 作品切换后旧响应回写 | 新作品界面展示旧作品信息 | 页面卸载或作品切换统一失效全部请求通道，响应前验证通道代次 |

## 4. Electron安全要求

```ts
webPreferences: {
  nodeIntegration: false;
  contextIsolation: true;
  sandbox: true;
  webSecurity: true;
  preload: PRELOAD_PATH;
}
```

还必须：

- 严格CSP，不允许`unsafe-eval`进入正式构建。
- Renderer只从`worldforge-app://renderer/`安全标准协议加载。
- Renderer不使用高权限`file://`页面；自定义协议不启用不必要能力。
- 拦截`will-navigate`、`setWindowOpenHandler`和下载行为。
- 不加载用户提供的HTML为应用页面。
- 正式构建受控开放DevTools。
- Electron Fuses在安全测试中持续验证。
- MessagePort、Provider和Generation IPC只暴露具名、可验证、可撤销的最小能力。
- 关闭前当前稿刷新只接受当前应用页面、匹配请求标识且通过strict Schema的结果；失败或超时不静默退出。

## 5. 数据库与文件威胁

- 每个项目使用独立数据库和目录。
- 写队列不接受原始SQL、表名或路径作为Renderer输入。
- 备份使用SQLite Online Backup，不直接复制打开中的数据库。
- Migration、导入、建议稿采用、批量替换和结构操作前创建恢复点。
- FTS、统计、摘要和缓存损坏时重建，不反向污染业务表。
- 情节骨架Payload与正文建议稿块分离，类型转换必须通过明确业务命令。
- GenerationRun成功与建议稿或设定更新建议结果引用原子提交。
- 批量替换只修改活动当前稿正文块；历史版本不可变，实体使用专用命令。
- 三轨备份清理保护最后已验证备份、永久恢复点和作者保留快照。

## 6. AI边界

- Prompt中的“不要修改锁定段落”只是质量提示，真正保护由Core完成。
- Renderer锁定样式和禁用态不是权限边界；绕过Editor直接调用Core仍执行保存序号、Hash、归属、建议稿类型与LockGuard校验。
- 同一正文补丁只要存在一个锁定冲突就不持久化任何操作。
- 模型输出必须经过Schema解析和业务校验。
- T1输入只允许持久化情节骨架、权威场景节拍或直接章节目标。
- 未完成建议稿只能显式补全、保存或丢弃，不能默认作为完整稿。
- AI状态提取只生成pending设定更新建议，`previousValue`由Core计算。
- pending建议不参与权威连续性、弧光或语义校验。
- 未验证模型不允许绕过代码硬保证。
- 所有生产Provider调用经过有界Fetch；不能先完整缓冲再检查资源上限。
- Provider超限使用`AI_RESPONSE_TOO_LARGE_014`，不保存原始响应或伪装为普通结构解析失败。

## 7. Provider响应资源边界

```text
单次原始响应总量：16 MiB
单个SSE事件：1 MiB
```

- 有效`Content-Length`声明超限时，在读取正文前取消。
- 无长度声明或声明不可信时，按实际流式字节累计。
- SSE按空行边界统计，兼容LF、CRLF和跨分片边界。
- 无分隔符事件仍受单事件上限保护。
- 超限后取消底层Reader，停止未来解析和事件交付。
- 上限调整必须经过安全、性能、协议和测试同步评审。

## 8. 异步界面状态边界

- 搜索、替换、作品词典和全文索引是同一页面内的独立异步通道。
- 同一通道后发请求使先发响应失效；不同通道不得相互失效。
- 每个通道只允许其最新请求清理自身等待状态。
- 作品切换和页面卸载统一使全部通道失效。
- Renderer临时状态不承担权威写入安全；词典和替换写入仍由Core项目边界、锁定、预览计划和事务保护。

## 9. 凭据与网络边界

- Credential Broker通过Electron `safeStorage`安全后端加密，密文落盘但不进入数据库。
- 凭据文件与目录使用平台可达的最小权限。
- 凭据值只在请求期受控内存存在，不发送给Renderer。
- Provider配置区分本机、局域网和外部端点。
- Provider端点禁止`file://`、应用内部协议、云元数据地址和未批准Custom脚本。
- 跨主机重定向默认拒绝。
- 外部Provider如何保存请求属于剩余风险，必须由界面明确提示。

## 10. 剩余风险

V1.0不解决：

- 设备被完全控制后的本地数据保密。
- 用户自行配置的不可信模型服务如何处理请求。
- 用户自行将项目放入第三方同步盘后的冲突。
- 未启用磁盘加密时共享设备上的明文项目数据库访问。
- 操作系统安全加密后端本身被破坏后的凭据保密。
- 物理内存极低设备在合法但接近上限的大响应下仍可能出现性能压力。

这些风险需要在用户文档中明确，不得误导为“绝对安全”。

## 11. 安全验收

- Renderer访问`require`、`process`、数据库和文件系统失败。
- 未注册IPC和非法字段被拒绝。
- 路径越界、符号链接逃逸、危险Provider端点和跨项目ID测试失败关闭。
- 锁定、建议稿隔离、情节骨架类型、未完成限制和保存序号冲突硬保证为0缺陷。
- AI直接写权威状态、pending冒充事实和跨项目建议成功次数为0。
- 取消后未来delta进入Renderer次数为0。
- Run—建议稿—设定更新建议—Prompt—约束引用完整。
- safeStorage不可用和不安全后端时凭据操作被阻断。
- 默认日志、诊断包和继续写作状态扫描不含正文与凭据。
- Provider声明总量、实际总量和单SSE事件超限均安全失败。
- 词典操作不再使在途搜索或替换永久等待；作品切换后旧响应不回写。

## 12. 本地文本与DOCX文件边界

- Renderer无任意路径能力；源文件和目标目录只由Electron Main系统选择器产生。
- Core拒绝非绝对路径、符号链接、非普通文件、未知扩展、二进制NUL、空内容和超限输入。
- 自动检测采用严格解码；低置信度编码必须在预览界面可见并允许人工重选。
- ImportPlan绑定源文件Hash并设置有效期，文件变化或过期阻止提交。
- DOCX限制解包总量、文件数、压缩比、嵌套深度和关系目标，忽略宏、OLE和外部资源。
- 导出文件名禁止路径分隔符、控制字符和`..`；同名文件绝不静默覆盖。
- 导出经同目录临时文件、内容Hash验证和原子重命名完成，失败清理临时文件。
