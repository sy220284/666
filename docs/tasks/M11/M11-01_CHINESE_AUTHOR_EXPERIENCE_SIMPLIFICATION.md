## 目标

在不削减现有产品能力、不修改现有权威数据语义的前提下，先完成 V1.1 的中文作者语境基线和第一批高频交互减负，为后续 AI 审阅、灵感胶囊、人物关系/时间线可视化建立稳定的作者层入口。

## 本任务接入原则

- 内部类型、协议与数据库英文标识保持稳定，不为界面中文化制造无意义数据迁移。
- 用户可见层统一采用中文网文作者自然语言。
- 普通模式不要求作者输入 JSON、UUID、Revision、Schema 或正文段落内部标识。
- 当前 `StateProposal` 继续作为 AI 设定建议权威入口，本任务只改善展示和作者编辑方式，不提前引入 M11-02 的统一 ReviewProposal 数据模型。
- 当前 Planning/Canon/Checks 路由和 Core Bridge 接口保持兼容，避免在体验任务中混入大规模协议重构。

## 实施范围

### A. 作者术语基线

统一展示层正式名称：

- `作品任务书` → `作品核心`
- `场景节拍` → `场景`
- `建议稿` → `AI建议稿`
- `正文块` → `正文段落`
- `已确认设定` → `人物与世界`
- `设定更新建议` → `AI设定建议`
- `作品检查` → `内容检查`
- `写作待办` → `修改任务`

保留历史数据库、IPC、类型名和内部 data attribute，不扩大迁移范围。

### B. 规划入口中文化

- `ProjectBrief` 标题改为 `作品核心`。
- 简明/完整规划说明使用“作品核心、场景”等统一中文作者术语。
- 现有模式切换行为保持真实设置单一所有权，不另建局部模式状态。

### C. AI 设定建议作者化

- 页面标题、批次、建议、来源等文案统一为作者语言。
- 可信度从百分比改为 `高 / 中 / 低`，避免伪精确。
- `编辑后接受` 不再要求填写 JSON。
- 对人物/世界动态状态按字段类型提供文字、数字、是/否、多行清单的作者输入。
- 对人物成长节点使用中文状态选择语义；无法安全转成普通作者输入的未知结构禁止技术式编辑，仍允许接受或忽略。
- 原始 JSON 只保留在折叠的技术详情中用于诊断。

### D. 高频结构操作减负

- 场景关联正文时直接勾选正文段落预览，不再要求手填段落序号或内部标识。
- 从正文创建场景时先选择原文段落，再填写场景信息；正文内容和顺序不被隐式改写。
- 拆章直接选择原文拆分位置，继续保留影响预览、`planHash` 和恢复点保护。
- 跨章移段直接选择待移动正文与目标插入位置，已锁定段落不可选择；继续保留影响预览、冲突检查、`planHash` 和恢复点保护。
- 知情状态的来源正文从所选定稿中直接选择原文段落，内部正文标识由系统保存。

### E. 回归保护

增加或调整 Renderer 单测，至少覆盖：

- 正式作者术语映射。
- AI 设定建议可信度标签。
- 动态状态的编辑后接受不再走 JSON 输入。
- 列表、数字、布尔等作者输入能够转回现有 `editedValue` JSON 值。
- 过期建议继续只允许忽略/拒绝，不能被编辑接受。
- 场景正文选择入口在可编辑与只读状态下保持正确语义和写入保护。
- 高频结构操作仍保留原有预览、锁定、`planHash` 和恢复点边界。

## 明确不在本任务完成

以下能力由后续任务承接：

- 统一 AI 审阅数据模型与定稿后自动分析。
- 人物关系持久化模型。
- 时间线/人物关系/伏笔/成长路线可视化。
- 灵感胶囊。
- 文风档案、模型任务路由、长期摘要。
- 拆章、移段、场景之间的完整拖拽重排；本任务仅完成正文段落的可视化选择与现有安全写入链复用。
