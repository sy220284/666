# WorldForge 任务卡模板

> 状态：Active  
> 适用：历史独立任务、M4-04整体任务和未来单独立项任务  
> 原则：任务文件保留可导航需求；活动任务必须有机器授权、完整执行附件和真实证据。

## 1. 当前任务结构

```text
历史独立任务
├─ M0—M3
└─ M4-01—M4-03

当前唯一整体任务
└─ M4-04 V1剩余功能整体实施与发布闭环

被吸收需求来源
└─ 原M4-05—M8-03
```

被吸收来源保留详细目标、非目标、合同、测试和完成条件，但不得独立激活、建立正式功能分支/PR或单独关闭。

## 2. Planned任务卡

普通Planned任务卡应包含：

1. 基本信息、状态、优先级和建议分支。
2. 目标、阶段定位和非目标。
3. 依赖与承接基线。
4. 关联需求、功能ID和P0验收。
5. 必读文档与主要影响范围。
6. 职责边界与实施内容。
7. 测试、证据和完成条件。

已完成任务卡保持冻结；后续发现的扩展由当前活动任务承接。

## 3. 整体任务附加要求

整体任务除普通字段外，必须包含：

- 被吸收需求来源完整清单。
- 编码前全量代码与文档审计门。
- 已有、缺失、冲突和可复用能力矩阵。
- 需求→用户路径→代码层→测试→P0映射。
- 共享合同、Migration、IPC、错误码和共享入口总计划。
- 内部实施阶段和原子提交组。
- 每阶段横向、纵向复查与受影响回归。
- 统一证据目录和最终发布关闭标准。
- 最终任务关闭后不自动激活下一任务的规则。

整体任务内部阶段不是独立任务，不改变`ACTIVE_TASK`。

## 6. Definition of Done

任务只有同时满足以下条件才能标记Verified：

- 目标真实接通，非目标未提前引入。
- 已完成依赖和历史任务卡保持冻结。
- 用户功能形成Contracts→Core→Main→Preload→Renderer→测试纵向闭环。
- 成功、失败、取消、冲突、只读、恢复和重启路径覆盖。
- Schema、Migration、IPC、事件、错误码、UI、安全和文档同步。
- 测试真实运行并记录退出状态。
- 证据绑定实际受检Head和可达main提交。
- 无TODO、空函数、固定假数据和伪造成功。
- 任务索引和追踪矩阵同步。
- 被吸收需求没有遗漏或被错误视为删除。

- M4-04是V1剩余功能唯一整体任务。

- 原M4-05—M8-03只作为需求来源。
- 统一证据目录为`docs/test-evidence/M4-04/`。
- 最终Verified后不自动开始下一任务。
