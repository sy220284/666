# 已知风险与回退

## 风险

1. SQLite、内存 Task 与 Provider 不共享单一事务。Generation 通过每 Run FIFO 生命周期锁、取消状态持久化先行和 Candidate 持久化不可取消区形成顺序闭环；后续修改阶段切换或锁边界时必须保留竞态故障注入测试。
2. 命令身份依赖稳定规范化输入。新增字段、默认值或序列化规则时必须同步更新指纹输入与跨进程重放测试，禁止仅按 `requestId` 回退。
3. 活动 Run 的同请求重放依赖内存任务索引，跨进程重放只返回持久 Run，不自动再次调用模型。若未来引入恢复执行器，必须使用显式状态租约，不能把查询重放改成隐式重启。
4. Recovery 横跨 SQLite 与文件系统，仍采用补偿语义。清理失败必须保留主错误、继续其余清理并记录受限残留，不得恢复为首个删除错误覆盖业务错误。
5. Renderer 代次守卫依赖新 Run 启动、终态读取与候选加载共享同一 Generation 代次。后续拆分组件时必须保持纯刷新流程测试与旧 Run 失效断言。
6. 工具链 Artifact 绑定 Linux X64 与精确提交。它用于当前质量工具离线复现，不代表 Windows/macOS 产品打包产物；跨平台发布仍由永久平台矩阵负责。
7. Windows Native IME 与 Package Smoke 由路径路由决定是否执行。本任务未修改输入法组合事件或打包输入，Quality 聚合只接受永久工作流给出的规范化终态。

## 回退

按命令身份缓存、Project/Database 命令传播、Generation 创建与取消、Provider Abort、Recovery 补偿、Renderer 代次刷新、永久工具链工作流及对应测试整体回退。

回退不得恢复跨命令静默重放、不同输入共用成功结果、取消状态与 Candidate 持久化并发、Provider 预取消遗漏、补偿错误覆盖主错误、旧 Run 覆盖新候选，或不含 `.bin/.pnpm` 的不可直接执行工具包。
