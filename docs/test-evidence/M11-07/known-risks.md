# M11-07 已知风险

1. 故事摘要是可重建派生资料，不是权威事实。后续能力必须继续通过现有约束包回查人物、世界、连续性和正式定稿，不得只信摘要。
2. 当前语义证据门没有触发向量层：所有关键场景由 FTS、结构或摘要上下文召回，只有一项非关键释义缺口。只有新的真实关键漏检证据达到决策阈值，才可另行立项。
3. 正文学习文风需要至少两份同项目定稿；文风偏离只做提醒，不阻止保存、生成或定稿，也不得复制网文章奏设置的职责。
4. 智能任务分配只能使用已有受信连接和已保存凭据。模型支持记录必须绑定精确任务、模型、Prompt ID 和 Prompt Version；未验证不等于支持。
5. 300万—500万字测试使用确定性合成长篇正文，覆盖数据规模、SQLite、摘要、搜索、上下文、备份恢复和堆增长，但不替代不同作者文本分布的长期遥测。
6. 本地容器没有 Linux 图形显示服务，桌面 E2E 只能在 GitHub Actions 标准 runner 上形成权威证据。
7. 本地全仓性能并跑时，既有强制 GC 探针曾在资源重负载下触及 150 秒子进程上限；同一探针独立运行且全部内存预算通过。永久门禁若在标准 runner 失败，必须以运行日志为准，不得以本地独立通过覆盖 CI 事实。
8. `IMPLEMENTED` 是合并前静态状态；最终有效 `VERIFIED` 必须同时满足来源绑定、Controlled Merge、`main-verification` 与 `task-verification/M11-07` 成功。
