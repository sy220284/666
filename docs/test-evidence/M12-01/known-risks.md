# M12-01 已知风险与边界

## 历史定稿时间

M12-01 之前的项目没有独立 `finalized_at`。迁移只能将当前终稿 Version 的 `created_at` 作为历史最佳锚点；迁移之后的终稿切换会记录实际时间。该限制只影响旧数据的历史回溯精度，不影响新操作。

## 手动周期与项目时区

每日/每周自动补偿严格使用项目 IANA 时区。当前 Renderer 的“今日/本周/指定日期”按本机日历输入换算为绝对时间窗口；当设备时区与项目时区不同，作者手动选择的自然日语义可能与自动周期不同。数据边界仍是明确的绝对时间，不产生跨项目或正文写入风险。后续如统一手动自然日语义，应复用 Core 的项目时区计算，不新增第二套周期算法。

## 智能复盘

模型输出属于可重建解释层。Provider 不可用、输出失败或运行取消时，确定性摘要与作者备注继续可用；Journal AI 状态与 GenerationRun 终态联动。智能结果必须通过来源 Hash 与运行身份校验，不能提升为故事权威事实。

## 性能

Journal 的确定性摘要读取时间窗口元数据与已有 StoryDigest，不读取 Version/Draft 正文块。500 万字符专项用于验证正文规模不会线性放大一日窗口聚合；最终性能结论只接受实际 `pnpm test:perf` 或对应权威工作流结果。

## 恢复与克隆

Journal preferences 与 entries 进入现有项目 Clone Policy。恢复副本会重映射项目身份并保留 Journal entry identity 与作者备注；外键完整性由恢复流程和专项测试共同约束。
