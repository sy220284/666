# 检查工作台与后台刷新连续性

- 内容检查、搜索、节奏、任务与批注四个分区复用现有业务组件和各自状态所有权。
- 四个分区始终保持挂载；切换仅改变可见性，因此搜索条件、节奏参数、检查结果和任务／批注筛选不会丢失。
- `tests/unit/m11-checks-workbench-interactions.test.ts` 验证四个分区的挂载和跨分区筛选状态保持。
- Generation 任务事件仍为状态刷新主通道；失联时使用现有单飞能力执行 15 秒兜底轮询。
- 全仓审计确认未新增持续高频 `setInterval`，并断言刷新使用单飞请求和固定兜底周期。
- 保存、恢复、Continuation、Undo、Candidate Apply 与结构保护继续由现有全量单元、集成、可靠性和 Electron 门禁覆盖。
