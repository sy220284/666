# M12-04 已知风险与持续约束

1. 应用关闭握手需要同步决策，因此只有 `runtime/unsaved-changes.ts` 内经过注释和回归测试的关闭安全兜底保留原生确认；普通功能和异步导航不得重新引入原生 `prompt/confirm`。
2. 研究筛选保留当前编辑对象，因此被列表条件排除的笔记仍应显示明确提示；真实对象切换、删除、归档和离开工作台必须继续执行未保存保护。
3. 三条创作路径只影响作者入口、推荐和说明；后续扩展不得复制路由、业务权限、GenerationRun 或 Candidate 写入协议。
4. 简明模式隐藏运行标识、模型提供方、修订序号和采用记录；完整模式的技术详情只用于诊断，不得改变作者确认或只读边界。
5. 内容检查四分区依靠保持挂载保存本地状态；新增分区时应复用既有业务组件，避免引入第二套检查、搜索、批注或节奏状态真源。
6. 任务事件仍为主通道，15 秒单飞轮询只用于失联兜底；不得因为界面切换新增持续高频刷新或并发重叠请求。
7. 8K／20K 指标由真实 SQLite 写事务和中文章节样本记录；运行机负载会影响绝对耗时，但统计 50ms、自动保存 150ms 的预算不得放宽。
8. 合并前静态状态只证明冻结实现和验收材料已经收口；最终有效验证由 Controlled Merge 后发布的 `main-verification` 与 `task-verification/M12-04` 决定。
