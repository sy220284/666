# 100% 覆盖率测试专项

## 目标

在现有统一 V8 覆盖分母和已审计显式排除边界上，将生产源码的 statements、branches、functions、lines 四项覆盖率收口到 100%。

## 起始基线

基于 `main@674b57f2240216a26ace91263f5af18a25e87fb7` 的正式 Quality 产物：

| 指标 | 总量 | 已覆盖 | 未覆盖 | 起始覆盖率 |
| --- | ---: | ---: | ---: | ---: |
| statements | 21,869 | 16,995 | 4,874 | 77.71% |
| branches | 14,471 | 9,919 | 4,552 | 68.54% |
| functions | 5,177 | 3,863 | 1,314 | 74.61% |
| lines | 19,832 | 15,840 | 3,992 | 79.87% |

起始测试结果：413 个测试文件、1,635 条测试全部通过。

## 规则

1. 禁止通过新增覆盖率排除项、降低阈值、扩大忽略注释或删除有效业务分支抬高数字。
2. 优先补真实用户行为、失败路径、空状态、只读状态、竞态、取消、生命周期和恢复路径。
3. 对类型契约已经证明不可达的代码分支，允许做语义等价的穷尽化重构；必须同时保留契约测试，禁止仅为统计数字删除防御能力。
4. 每轮正式 Quality 后使用 `coverage/coverage-final.json` 重新排序真实缺口，不按测试文件数量判断进展。
5. 现有 `coverage-exclusions.json` 只能缩减，专项期间不得增长。排除项仍必须维持替代测试和退出条件。
6. 四项真实达到 100% 后，将 `vitest.coverage.config.ts` 的最终门禁固定为 100%，并增加政策测试防止回退。

## 收敛顺序

按未覆盖量从大到小推进：

1. Renderer 大型交互工作台与面板。
2. Core Service 恢复、生成、来源解析与任务协议。
3. Main / Preload IPC 与桥接工厂。
4. Editor Core、Contracts、Domain、Prompts 的剩余边界。
5. 全仓零散单分支、空值与异常路径。
6. 排除登记复审与可移出模块补测。

## 第一批

- `SearchPanel`：搜索过滤、来源标签、导航、替换预览/应用、词典、索引重建、只读、失败和异步陈旧响应。
- `GenerationSourceResolver`：直接目标、重写陈旧/锁定/Unicode、结构重写、当前稿/候选稿合并、来源丢失和最终版本。
- `utility-errors`：数据库、项目、候选稿、恢复、导入导出、设定、连续性等错误码映射矩阵。

第一批完成后必须重新读取正式 `coverage-final.json`，以真实增量决定第二批，不按测试条数推测覆盖效果。

## 完成条件

- statements = 100%。
- branches = 100%。
- functions = 100%。
- lines = 100%。
- 正式 Quality / Security / Performance / Reliability / Electron E2E 按风险矩阵全部通过。
- 覆盖率排除登记未增长；可测试边界优先移出排除表。
- 覆盖率门禁已固定为 100%，后续代码无法静默回退。
