# WorldForge 安全测试用例

> 状态：Approved  
> 依据：`SECURITY.md`、`THREAT_MODEL.md`、冻结ADR和P0硬保证。  
> 更新日期：2026-07-30

## 1. Electron隔离

| ID | 场景 | 步骤 | 预期 |
|---|---|---|---|
| SEC-001 | Renderer访问Node | 在Renderer尝试读取`process`、`require`、`fs` | 均不可用，应用不崩溃 |
| SEC-002 | 原始IPC访问 | 尝试调用未暴露channel | 无通用接口，命令无法发送 |
| SEC-003 | 不安全脚本 | 正式构建注入`eval`或内联脚本 | CSP阻止并记录安全事件 |
| SEC-004 | 应用内远程导航 | 点击或脚本跳转外部URL | 当前窗口不导航，允许的外链交系统浏览器 |
| SEC-005 | 新窗口 | 页面请求`window.open` | 被拦截或交系统浏览器，不创建高权限远程窗口 |

## 2. IPC契约

| ID | 场景 | 预期 |
|---|---|---|
| SEC-006 | 未注册命令 | 返回输入或命令错误，不进入Core Use Case |
| SEC-007 | 多余字段 | strict Schema拒绝 |
| SEC-008 | 非法枚举和超长字符串 | 拒绝并返回稳定错误码 |
| SEC-009 | 协议版本不匹配 | 只允许健康检查和安全退出 |
| SEC-010 | 重复requestId | 写操作只执行一次，返回原结果 |
| SEC-011 | 伪造projectId | Core拒绝，数据库无变化 |
| SEC-012 | 伪造实体ID跨项目 | Core拒绝，源项目和目标项目均无变化 |

## 3. 路径与文件

|---|---|---|
| SEC-013 | `../`路径穿越 | 规范化后发现越界并拒绝 |

## 4. 当前稿、建议稿与锁定

| ID | 场景 | 预期 |
|---|---|---|
| SEC-019 | AI流式输出 | 当前稿内容和保存序号不变化 |
| SEC-020 | 未确认建议稿 | 当前稿不变化 |
| SEC-021 | 旧保存序号采用 | 返回冲突，不静默覆盖 |
| SEC-022 | 正文块Hash变化 | 目标块进入冲突集 |
| SEC-023 | 锁定块更新 | Editor和Core均拒绝 |
| SEC-024 | 锁定块删除或移动 | 操作拒绝或明确跳过 |
| SEC-025 | 批量替换命中锁定块 | 预览标记并默认跳过 |
| SEC-026 | 历史版本修改 | Repository无更新路径或明确拒绝 |
| SEC-027 | 未完成建议稿定稿 | 拒绝，要求先确认或转完整稿 |

硬指标：锁定块破坏、未确认建议稿写入和保存序号静默覆盖均为0。

## 10. Provider响应资源耗尽

| ID | 场景 | 步骤 | 预期 |
|---|---|---|---|
| SEC-061 | 声明响应超限 | Provider返回大于16 MiB的`Content-Length` | 读取正文前取消响应体，返回`AI_RESPONSE_TOO_LARGE_014` |
| SEC-062 | 实际流式总量超限 | 无可信长度声明，分片累计超过16 MiB | 取消底层Reader，不继续缓冲或解析，返回`AI_RESPONSE_TOO_LARGE_014` |
| SEC-063 | 单个SSE事件超限 | `text/event-stream`单事件超过1 MiB，包含无分隔和跨分片情况 | 在事件完成前停止读取，返回`AI_RESPONSE_TOO_LARGE_014` |

共同要求：

- 超限后当前稿、建议稿、设定更新建议和GenerationRun结果引用不得伪装成功。
- 不记录原始超限响应正文。
- `AI_OUTPUT_INVALID_008`不得用于上述资源超限场景。
- 基础写作和本地数据保持可用。

## 11. 异步界面隔离

| ID | 场景 | 预期 |
|---|---|---|
| SEC-064 | 搜索期间保存或删除词典 | 词典操作不使搜索通道失效，搜索等待状态正常结束 |
| SEC-065 | 同通道后发请求 | 先发响应不能覆盖后发结果，只有最新请求清理对应等待状态 |
| SEC-066 | 作品切换 | 搜索、替换、词典和索引全部旧响应失效，不写入新作品界面状态 |

该组主要保护界面状态完整性，不将Renderer临时状态视为权限边界；所有权威写入仍由Core项目边界和事务保证。

## 12. 自动化与证据

- 单元/集成测试覆盖SEC-006—041、SEC-050—066。
- Playwright覆盖SEC-001—005、017、018和关键UI提示。
- 异常DOCX Fixture覆盖SEC-042—049。
- Provider有界Fetch测试覆盖声明总量、实际总量和单事件三条超限路径。
- 每次Electron、Preload、路径、Migration、建议稿采用、Provider和备份变更必须运行相关安全用例。
- 结果保存到`docs/test-evidence/<TASK-ID>/security/`或四件套命令记录。

任一Critical或High用例失败时禁止合并。

## 13. 恢复与结构操作既有基线

- SQLite在线备份必须通过`integrity_check`、`foreign_key_check`和SHA-256验证后才登记。
- 空间不足、备份损坏、恢复中断和目标冲突不得留下可选中的未验证恢复点或部分项目。
- 数据库损坏时项目只能只读打开；外部已验证恢复点仍可恢复到新目录。
- 拆章、合章和跨章移动在恢复点前执行读预检，事务内重校验计划Hash、保存序号、内容Hash与锁定保护。
- 永久删除在历史版本或建议稿引用存在、预览过期、标题不匹配或用户取消时拒绝。
