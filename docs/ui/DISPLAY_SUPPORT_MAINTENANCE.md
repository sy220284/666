# WorldForge 现行显示支持矩阵维护附录

> 状态：Approved Maintenance
> 生效日期：2026-08-15
> 适用：桌面端正式显示支持、窗口默认尺寸、平台体验、DPI、视觉回归与发布验收
> 权威关系：本附录覆盖现行文档中关于 FHD、1280×800、1024×640 作为“正式显示器支持/发布阻断矩阵”的旧条款；历史任务卡与历史 Evidence 保留原记录，不回写历史事实。

## 1. 现行正式支持

正式物理显示器与发布阻断矩阵从 QHD 起步：

| 档位 | 物理分辨率 | 定位 | 验收角色 |
|---|---:|---|---|
| QHD | 2560×1440 | 正式最低支持 | 严格视觉基线、三平台主基线、DPI 主矩阵 |
| QHD+ 16:10 | 2560×1600 | 中高端笔记本 | 三平台纵向空间与弹层验收 |
| UWQHD 21:9 | 3440×1440 | 中高端超宽屏 | 工作区限宽、操作距离与超宽布局 |
| 4K UHD | 3840×2160 | 高端桌面 | 高分屏、缩放与大工作区验收 |

1920×1080（FHD）以及更低物理分辨率不再属于正式支持矩阵，也不作为发布阻断目标。

## 2. CSS/DIP 降级与物理显示支持分离

Renderer 继续按 CSS px / DIP 有效视口响应。`<1440px` 等窄视口断点保留，用于：

- QHD / 4K 在 150%—200% 系统缩放后的有效视口；
- 用户主动把窗口缩窄；
- 混合 DPI 多显示器迁移；
- 窗口恢复时的安全夹取。

这些断点只证明界面能安全降级，不构成对 FHD、1280×800、1024×640 等物理显示器的产品支持承诺。

## 3. DPI 与窗口策略

- QHD 必须覆盖 100%、125%、150%、200% 系统缩放。
- QHD+、UWQHD、4K 至少覆盖系统推荐缩放与 100% 基线；高 DPI 行为继续通过 CSS/DIP 断点验证。
- UI 缩放、系统 DPI、正文字号、正文宽度继续相互独立。
- 首次启动默认窗口调整为 1600×1000 DIP，并按可用工作区夹取。
- `720×520` BrowserWindow 最小值仅作为窗口缩放/恢复安全下限，不代表正式硬件支持下限。

## 4. 严格视觉回归

Linux 严格像素基线统一迁移到 **2560×1440 @100% / device scale 1**。Theme A/B 的浅色与深色四套基线均使用稳定帧双见证：

1. 规范化滚动、焦点、鼠标位置；
2. 双 `requestAnimationFrame` 等待绘制；
3. 连续两张 PNG 字节完全一致后才接受采样；
4. 两个独立 GitHub Actions Head/run 收敛到相同 PNG 后，才允许更新基线。

## 5. 发布验收矩阵

正式矩阵：

```text
2560×1440 @100%
2560×1440 @125%
2560×1440 @150%
2560×1440 @200%
2560×1600 @100%或系统推荐缩放
3440×1440 @100%或系统推荐缩放
3840×2160 @100%或系统推荐缩放
混合 DPI 双显示器
```

验收必须覆盖：首页、写作、侧栏/抽屉、候选/冲突、设置、导入预览、备份恢复、浮层边界、主题切换、无整页水平滚动和窗口恢复。

## 6. 历史文档处理

M0-06、M7、M8 等已完成任务中的 1280×800/FHD Evidence 是当时验证事实，继续保留。后续实现、测试与发布判定读取本附录和现行机器矩阵，不得引用历史低分辨率 Evidence 恢复旧支持策略。
